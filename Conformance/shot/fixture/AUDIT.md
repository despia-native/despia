# Self-audit of the 40-strip renders, defect by defect

Held against the five reference sets, harshly. Root causes, not symptoms.

| # | Defect (measured) | Root cause | Fix |
|---|---|---|---|
| A1 | The APP inside the phone reads as a wireframe: hairline separators, 15px grey text, no colour, no shape. Every slide inherits this. | The demo app was written as a test fixture, not as a designed app. The references' inner screens are chunky cards, tinted icon tiles, bold numbers. | Redesign the fixture app screen itself: stat tiles, tinted letter tiles per row, bold prices, taller rows. The showcased app must be a designed app. |
| A2 | The phone's UI text is small relative to the slide (device at 96% of a 396px card puts app text at ~13px slide-space). "Bigger phone" must mean BIGGER UI. | deviceWidth is capped at 100% of the column; references render the device at 110-130% of the card, bled edge to edge, so the visible UI is large. | Centre the device with left:50% + translateX(-50%), allow deviceWidth > 100%, drop the crop box's side padding so the phone bleeds to the card edges. |
| A3 | Dead white bands: strip-1 has ~25% of the card empty between the fade tail and the laurel; strip-3 has ~28% empty above a lone chip. | Decor placed BELOW the dissolve instead of overlapping it; crop heights chosen shorter than the space available. | Decorations overlap the dissolve zone (references lay panels over the fading phone); crops sized so content + dissolve fill the card. |
| A4 | Grey plumes: the dark rails smear through the fade on tall crops (strip-3 to ~y1450). | Dissolve bands and gradient are sized as PERCENT OF THE CROP, so a tall crop dilutes the gradient exactly where the rails are darkest. | Fix the dissolve to PIXEL heights hugging the bottom edge - same depth at every crop height. |
| A5 | strip-3's rating badge overlaps the app's header text; the composition reads as collage, not layout. | Decor tuned by eye against a screenshot instead of against measured boxes. | Probe-measure the app's row boxes and place decor against numbers. |
| A6 | The device's drop shadow ends in a hard vertical band 34px inside the card. | The copy column carried `overflow: hidden` plus side padding and HELD THE DEVICE, so the shadow clipped at an inner box no design ever drew. | One clip boundary: the card. The device band is a card-level sibling of the copy block; nothing clips inside the card. |
| A7 | Chips tuned for one layout landed on top of the app's greeting after the layout changed; nothing refused the image. | The decoration layer was a freeform percent-of-card overlay with no relationship to the boxes it decorated and no rules. | The scene obeys DSX: chips are FLOW (they reserve space), decor rows anchor to a named box (`at: "device"`), and covering readable UI requires `over: "screen"` or G-cover refuses the shot on the MEASURED frame. |
| A8 | The phone sat glued to the card border with no side breathing room; "bleed to the edge" was a design claim, not a design. | `deviceWidth` was allowed past the card edge in the name of a bigger hero - which makes the UI bigger by deleting the safe space every reference set keeps. | The 1rem safe inset is STRUCTURAL (crop-box side padding; 100% = the safe width) and G-safe enforces it on the measured frame; a decoration may cross it only by declaring `bleed: true`. |
| A9 | Every band boundary of the dissolve printed a visible seam across the dark rails - a hard line where crisp became blurred, then another where blurred became blurrier. | The "progressive" blur was three discrete backdrop bands (2 / 6 / 14px) butted edge to edge; a step function can only ever look like steps. | A TRUE progressive blur: six backdrop layers whose gradient masks crossfade across eight fenceposts, blur compounding 0.5 to 16px down the band, zero at the top eighth so the entry is seamless - the Apple/Chrome material. |
| A10 | Taglines broke to a one-word last line ("...from the first / set."), sat 14px at 0.58 opacity, and hung too far above the device; the strip was left-aligned by default. | The sub had no MEASURE, so it wrapped wherever the column ended - the orphan a typesetter kills first - and the copy-to-device gap was tuned before the device grew. | The tagline carries a measure in EM (`subMeasure`, data an agent tunes per slide), sits at 17px/1.4 at 0.66 (`subSize`, also data - and because the measure is in em, changing the size REBALANCES the wrap instead of reflowing it), and the gap tightened to 24px. `align` now defaults to CENTRE, with the auto-margin pair a measured block needs. |
| A11 | Every device faced the camera dead-on; a strip of five frontal phones has no depth and no variety, and floating cards had nothing to belong to. | The frame could only `rotate()` in the plane - a 2D spin, not a turn. | `lean` composes the CSS `perspective()` transform function, so the device rotates about its own Y axis with real foreshortening; a decor row may declare the same `lean` to share the camera, and `shine` rakes one specular across the cover glass. No 3D engine, because a projection is all this needs; the glass is NOT bent, because a cylindrical curve needs a mesh and faking it is worse than not doing it. |
