# Conformance — one fixture corpus, N runtimes

The shared tri-runtime test suite scaffolded by W0 (`/web/10-execution-plan.md`:
*"Scaffold `OpenSource/Conformance/{jse,api,lint,layout}/` folders + runner contracts"*).
Swift (the reference), Kotlin, and TypeScript all execute the SAME JSON fixtures —
*"corpora are platform-count-agnostic"* (`/web/10` R10), so Android joins without
restructuring anything here.

Runner contracts: the Swift side is the RECORD-MODE runner on Codemagic — the manual
`conformance-record` lane compiles the open kernel standalone (the Xcode project has no
test target; see `jse/README.md`), regenerates `jse/*.json` with the kernel's actual
results and fails on drift, so Swift doesn't just pass the corpus, it AUTHORITATES it.
vitest hosts TS, JUnit hosts Kotlin (rule 4 of `/STRUCTURE.md`). Gate G0: the corpus is
generated and green on Swift before any TS kernel code merges.

Working rules:
- Every cross-runtime divergence bug becomes a fixture in the same commit as its fix.
- New dual-platform capabilities (e.g. W5 `<api>`) land fixtures FIRST.
- The Android parity fixtures specced in `OpenSource/Skills/android/js-core-parity.md`
  (C1–R4) get their permanent home here as the Kotlin kernel lands.
